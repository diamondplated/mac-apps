# ScrollSplit

A small native menu-bar app for independent mouse-wheel direction and speed, plus four keyboard overrides. macOS 14 or later; universal Apple Silicon and Intel. ScrollSplit starts off. Choose **Turn On** from its menu when ready.

The menu shows whether ScrollSplit is On, Off or Needs Access, with **Turn On** / **Turn Off**, **Grant Accessibility…** and **Grant Input Monitoring…** (only while missing), **Settings…** and **Quit**. **Settings…** (⌘,) opens ScrollSplit's page in Mac Tools (`mactools://app/scrollSplit`), where every setting lives; if that page cannot open, it opens Mac Tools, and failing that asks you to install it. On its very first launch (once ever, and never when started as a login item) it offers the same alert. Opening ScrollSplit again while it is off or lacks access offers to turn it on; while it is working, nothing happens. Permissions are polled only while access is missing.

Discrete mouse-wheel events can reverse vertical and horizontal direction independently, with a 0.25×–4× speed multiplier. Fractional wheel ticks accumulate so slow speeds keep small movements. Continuous scrolling, scroll phases, modifier flags, source identity, and third-axis values stay unchanged. Settings apply live.

Three more switches live on ScrollSplit's page in Mac Tools. Each is off by default and does nothing while ScrollSplit itself is off:

- **Smooth scrolling.** Each notch of a wheel mouse becomes a short eased glide (0.2 s) of pixel scroll events instead of a jump, covering exactly the distance the notch would have scrolled; quick notches add to the glide, a notch the other way stops it, and Shift-scroll glides sideways. Trackpads, continuous-scrolling mice, and scrolling with ⌘, ⌃ or ⌥ held are left alone.
- **Back and forward buttons.** Pressing mouse button 4 sends ⌘[ (Back) and button 5 sends ⌘] (Forward) to the frontmost app, and ScrollSplit swallows those two buttons so the app never sees the click itself. If that is wrong for an app, such as a game that binds the side buttons, turn the switch off.
- **Pointer acceleration off.** Mice move the pointer at a constant rate while trackpads keep macOS acceleration. It is applied at launch, when a mouse connects, and on wake, and each mouse gets its previous setting back when the switch turns off or ScrollSplit quits. It uses a private macOS interface; where that is missing, the switch stays off and Mac Tools shows it unavailable.

## Keyboard overrides

Four more, each off by default and, like everything else, doing nothing while ScrollSplit itself is off:

- **Hold ⌘Q to Quit.** ⌘Q no longer quits straight away: holding it shows a small panel with the app's icon and a ring that fills, and the app quits only if ⌘Q is still held when the ring is full (about 0.8 s). Letting go sooner, pressing another key, changing modifiers or switching apps closes the panel and nothing quits. Only the app that was in front receives ⌘Q. The Finder and ScrollSplit's own menu are left alone.
- **Paste as Plain Text** (a shortcut, unassigned by default). Pastes the clipboard's text with all formatting removed, in any app. It puts only the text on the clipboard, sends ⌘V to the front app, then puts the original contents back half a second later, unless something else has changed the clipboard by then. ScrollSplit reads the clipboard only at the moment the shortcut is pressed, and never logs, keeps or sends what it contains.
- **Mute or Unmute Microphone** (a shortcut, unassigned by default). Toggles mute on the current default input device, using the device's mute where it has one and otherwise taking its input volume to zero and back. A new default device (a headset plugged in mid-call) is muted too while a mute is on. While muted, the menu bar icon becomes a crossed-out microphone and the menu's first line reads **Microphone Muted** with **Unmute Microphone** beneath it. The icon follows the device actually in use: a device with neither a mute nor an input volume cannot be muted and keeps the normal icon, and unmuting from Control Center or a call app is noticed. Turning ScrollSplit off or quitting it unmutes everything it muted.
- **Caps Lock as Hyper.** Caps Lock held with another key acts as ⌃⌥⇧⌘ held together, a layer of shortcuts no app uses. **While this is on, Caps Lock no longer locks capitals.** It remaps Caps Lock to F18 on each keyboard with a private macOS interface (the same one pointer acceleration uses); the mapping is not permanent, is reapplied when a keyboard connects and on wake, and only what ScrollSplit added is removed when the switch turns off or ScrollSplit quits, putting back any Caps Lock mapping you already had. Where the interface is missing, the switch stays off and Mac Tools shows it unavailable. A second switch, **Tap Caps Lock for Escape** (off by default), makes a quick press and release of Caps Lock on its own send Escape; without it a lone tap does nothing.

The two shortcuts are global hot keys, registered only while one is assigned; they need no event tap. Hold ⌘Q to Quit and Caps Lock as Hyper share one keyboard tap that exists only while either is on and passes every other key through untouched; the Caps Lock mapping is in place only while that tap is.

## Permissions and hardware limits

Turning on from the menu requests the native Accessibility and Input Monitoring permissions. Review these in System Settings → Privacy & Security. macOS may require reopening ScrollSplit after approval. Startup and the Mac Tools settings bridge never open consent prompts. Stable signing helps macOS retain grants across updates.

Public Quartz wheel events identify continuous scrolling, not physical mouse-versus-trackpad hardware. Trackpads and some high-resolution mice (including many smooth-scrolling drivers) both emit continuous events. ScrollSplit leaves all of those untouched. It customizes discrete wheel mice; it does not claim per-device identification. The speed multiplier scales incoming wheel deltas, not pointer acceleration. Secure Input, third-party drivers, or competing event taps can prevent custom scrolling. Disabling or quitting removes the tap. The side buttons use a second tap that exists only while that switch is on, and the keyboard overrides a third. Paste as Plain Text needs Accessibility to send ⌘V; muting needs no permission. Secure Input (password fields) hides keys from the keyboard tap, so Hold ⌘Q to Quit and Hyper do not act there. Some apps read modifier state directly from the keyboard rather than from the key event and will not see Hyper. macOS timeout-disabled taps are re-enabled while consent and the enabled preference remain valid.

## Development

Run `swift test --package-path ScrollSplit` from the repository root, then `ScrollSplit/build-app.sh`. The build script accepts `SCREENWREN_SIGNING_IDENTITY` and `SCREENWREN_SIGNING_TIMESTAMP` (`secure` or `none`); otherwise it uses the existing ScreenWren signing configuration when available, falling back to ad-hoc signing. It also works in an isolated package copy with those environment variables supplied. `ScrollSplit --self-check` performs pure checks without touching event hooks, hot keys, key mappings, the clipboard or the microphone, or asking for permissions. `SCROLLSPLIT_PANEL_SNAPSHOT=/tmp/scrollsplit-panel.png swift test --package-path ScrollSplit` also writes the hold-to-quit panel as `-light` and `-dark` PNGs beside that path.

## Settings bridge

`ScrollSplit --mac-tools-settings read` returns JSON with `schemaVersion: 1`, `app: "scrollSplit"`, `enabled`, `reverseVertical`, `reverseHorizontal`, `speedMultiplier`, `smoothScrolling`, `sideButtonsNavigate`, `mouseAccelerationOff`, `mouseAccelerationAvailable`, `holdToQuit`, `capsLockIsHyper`, `capsLockTapIsEscape`, `capsLockRemapAvailable`, `shortcuts`, `launchAtLogin`, `loginStatus`, `permissions`, and `eventTapStatus`. Writable properties are the eleven behavior/login Booleans and numbers plus shortcuts; `mouseAccelerationAvailable` and `capsLockRemapAvailable` are read-only, and `mouseAccelerationOff` / `capsLockIsHyper` read false and cannot be turned on while the matching one is false.

`shortcuts` uses ScreenWren's format, so the Mac Tools recorder works unchanged: every command in a fixed order (`pastePlainText` "Paste as Plain Text", then `toggleMicrophoneMute` "Mute or Unmute Microphone"), each `{command, title, shortcut}` with `shortcut` null or `{keyCode, carbonModifiers, keyEquivalent, keyLabel}`. Both start unassigned. A patch sends `"shortcuts": [{"command": …, "shortcut": … or null}]` (a `title` is accepted and ignored; snapshots regenerate it) with only the commands that change; key codes are 0–127, modifiers are Carbon Command, Control, Option and Shift and must include Command, Control or Option, and the resulting pair must not share a key combination. `"resetShortcuts": true` clears both and cannot accompany `shortcuts`. `write` accepts one JSON object on stdin; the entire patch is validated before any preference or login mutation. Unknown/read-only keys, nulls, mismatched Boolean/number types, and out-of-range speeds are rejected. Successful writes post `com.andrew.mactools.settingsChanged` for the existing app domain `com.andrew.scrollsplit`.

Runtime tap status comes from a live request/reply to the running app, matching its PID and canonical bundle path, not a persisted active flag. Multiple matching processes or a different running copy produce an explicit unknown status. `permissionsSource` distinguishes a running-app response from checks performed by the current CLI process. If the app does not reply, `eventTapActive` is omitted and `eventTapStatus` is `unknown`; an absent process returns `false`/`notRunning`. The CLI never installs a tap. No clipboard, keyboard, or mouse-event history is retained.
