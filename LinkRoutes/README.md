# LinkRoutes

A native macOS 14+ menu bar app that sends web links to the browser and profile you choose. LinkRoutes is a URL router, not a web browser: it never renders a page or records browsing history.

The menu shows whether LinkRoutes is routing links and offers **Make Default Browser…** (or **Restore <fallback> as Default…**), which uses the native macOS confirmation. **Settings…** (⌘,) opens LinkRoutes' page in Mac Tools (`mactools://app/linkRoutes`), where the fallback browser, rules and launch at login live; if that page cannot open, it opens Mac Tools, and failing that asks you to install it. Opening LinkRoutes again while it is not the default browser offers to make it the default; when it already is, nothing happens. Restore your fallback before uninstalling.

Rules run in displayed order, with the first usable match winning. Subdomains match on a dot boundary. If a rule's browser disappears, the next matching usable rule or configured fallback opens the link. A matching rule whose selected profile disappears stops routing and shows an alert with the reason and a **Settings…** button; work links never silently switch profiles. If the fallback disappears, LinkRoutes reports the problem the same way and never loops through the system default. Paths, queries, and fragments are passed to the chosen browser. Credential-bearing, malformed, non-web, and control-character URLs are rejected without logging their contents. Rules use ASCII hostnames/punycode. IPv6 links use the fallback browser; trailing DNS dots are normalized only for rule matching.

Browser discovery recognizes Safari, Chrome/Canary, Chromium, Edge, Brave, Firefox/Developer Edition, Opera, Vivaldi, Arc, Orion, and Zen, and verifies that each is an installed web handler. Other URL routers are excluded to prevent routing loops. Chrome, Edge, and Brave profiles come from their accessible `Local State` and existing profile directories. Other browsers use their default profile. Safari profile selection is not supported. Profile arguments are sent directly to the allowlisted browser executable through Launch Services, without a shell. A new Chromium process forwards the link to its existing browser instance. Browsers that ignore command-line profile selection may still use their own profile behavior.

All settings live in `com.andrew.linkroutes`. The validated, atomic settings bridge accepts `--mac-tools-settings read|write`, with a JSON patch on stdin for writes. Writable fields: `launchAtLogin`, `defaultBrowserIdentifier`, and `rules` (`id`, `domain`, `includeSubdomains`, `browserIdentifier`, optional `profileDirectory`). Read snapshots include `schemaVersion: 1`, `app: linkRoutes`, `loginStatus`, `availableBrowsers`, and `isDefaultBrowser`. Distributed notifications apply edits live. Registration as the default browser requires the native menu item and is deliberately not a bridge write.

Build with `./build-app.sh`; test with `swift test`. `--self-check` is pure and never registers a browser or changes preferences. Builds support both Apple silicon and Intel; signing uses `LINKROUTES_SIGNING_IDENTITY`/`LINKROUTES_SIGNING_TIMESTAMP`, common manager/ScreenWren environment overrides, or the suite's persistent local identity when present. No third-party dependencies.
