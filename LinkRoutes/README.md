# LinkRoutes

A native macOS 14+ menu bar app that sends web links to the browser and profile you choose, and opens files in different apps depending on which folder they are in. LinkRoutes is a URL router, not a web browser: it never renders a page or records browsing history.

The menu shows whether LinkRoutes is routing links and offers **Make Default Browser…** (or **Restore <fallback> as Default…**), which uses the native macOS confirmation. **Settings…** (⌘,) opens LinkRoutes' page in Mac Tools (`mactools://app/linkRoutes`), where the fallback browser, rules and launch at login live; if that page cannot open, it opens Mac Tools, and failing that asks you to install it. On its very first launch (once ever, never as a login item, and not if a link arrived) it offers the same alert. Opening LinkRoutes again while it is not the default browser offers to make it the default; when it already is, nothing happens. Restore your fallback before uninstalling.

Rules run in displayed order, with the first usable match winning. Subdomains match on a dot boundary. If a rule's browser disappears, the next matching usable rule or configured fallback opens the link. A matching rule whose selected profile disappears stops routing and shows an alert with the reason and a **Settings…** button; work links never silently switch profiles. If the fallback disappears, LinkRoutes reports the problem the same way and never loops through the system default. Paths, queries, and fragments are passed to the chosen browser. Credential-bearing, malformed, non-web, and control-character URLs are rejected without logging their contents. Rules use ASCII hostnames/punycode. IPv6 links use the fallback browser; trailing DNS dots are normalized only for rule matching.

A rule can also name the app a link was clicked in, such as Slack or Messages, alone or together with a website. LinkRoutes reads the sender of the link from the event that delivers it; when the sender cannot be determined (it has quit, or the link came from a command-line `open`), only rules without a source app can match. A rule's website may be `*`, meaning every site, and only together with a source app. Order still decides: the first matching rule wins. Two rules are duplicates only when website, subdomain setting and source app all match.

Before routing, LinkRoutes tidies the link, never contacting a server and never logging or storing it. **Strip tracking parameters** (on by default) removes `utm_*`, `fbclid`, `gclid`, `gclsrc`, `dclid`, `gbraid`, `wbraid`, `msclkid`, `mc_cid`, `mc_eid`, `igshid`, `yclid`, `twclid`, `ttclid`, `_hsenc`, `_hsmi`, `vero_id`, `oly_enc_id` and `oly_anon_id`, and leaves every other parameter and the fragment byte for byte as it was. **Open the destination of redirect links** (off by default) replaces Outlook Safe Links, `google.com/url`, Facebook `l.php` and Slack `slack-redir.net` links with the http(s) address written inside them, up to three layers deep, so rules match the real site; it is off by default because Safe Links exist so an organisation can scan a link first, and opening the destination skips that.

**File rules** open one file type in different apps depending on where the file lives, for example every `.md` under one folder in one editor and all other `.md` files in another. A rule has a file extension, an optional folder, and the app to open with; a file matches when its extension matches and it lies inside the folder (or the rule has no folder), and the first matching rule in list order wins. Folders are compared on resolved paths, so symbolic links, `..` and a trailing slash cannot dodge or wrongly trigger a rule, and `~` means the current user's home folder. LinkRoutes becomes the default app for a file type only while that type has a rule: saving the first rule for an extension records the app that was the default and makes LinkRoutes the default, and removing the last rule for it puts the recorded app back. That recorded app is also the fallback, so a file that matches no rule opens in it, and a rule whose app is missing falls back to it too; if neither is installed LinkRoutes shows an alert naming the file. LinkRoutes never opens a file with itself and refuses the common extensions that run code, install software or mount disks (`app`, `command`, `sh`, `zsh`, `bash`, `pkg`, `dmg` and similar). While any type is taken over, the menu lists them and offers **Stop Routing Files…**, which restores every recorded default at once; Mac Tools can do the same before uninstalling. LinkRoutes declares itself an alternate viewer of any document, so it is never the suggested app for a type without a rule. Restore file types (or choose another app in Finder with Get Info) before deleting LinkRoutes by hand.

Browser discovery recognizes Safari, Chrome/Canary, Chromium, Edge, Brave, Firefox/Developer Edition, Opera, Vivaldi, Arc, Orion, and Zen, and verifies that each is an installed web handler. Other URL routers are excluded to prevent routing loops. Chrome, Edge, and Brave profiles come from their accessible `Local State` and existing profile directories. Other browsers use their default profile. Safari profile selection is not supported. Profile arguments are sent directly to the allowlisted browser executable through Launch Services, without a shell. A new Chromium process forwards the link to its existing browser instance. Browsers that ignore command-line profile selection may still use their own profile behavior.

All settings live in `com.andrew.linkroutes`. The validated, atomic settings bridge accepts `--mac-tools-settings read|write`, with a JSON patch on stdin for writes. Writable fields: `launchAtLogin`, `defaultBrowserIdentifier`, `stripsTrackingParameters` (default true), `unwrapsRedirects` (default false), `fileRules` (the whole list: `id`, `fileExtension`, optional `folder`, `applicationIdentifier`; at most 100, no duplicate extension and folder, never LinkRoutes itself or a blocked extension), `stopRoutingFiles: true` (restores every recorded default and clears `fileRules`), and `rules` (`id`, `domain`, `includeSubdomains`, `browserIdentifier`, optional `profileDirectory`, optional `sourceBundleIdentifier`; `domain` may be `*` only with a source app). Read snapshots include `schemaVersion: 1`, `app: linkRoutes`, `loginStatus`, `availableBrowsers`, `isDefaultBrowser`, `fileRules`, and the read-only `takenOverExtensions`. Distributed notifications apply edits live. Registration as the default browser requires the native menu item and is deliberately not a bridge write.

Build with `./build-app.sh`; test with `swift test`. `--self-check` is pure and never registers a browser, changes a default app or changes preferences. Builds support both Apple silicon and Intel; signing uses `LINKROUTES_SIGNING_IDENTITY`/`LINKROUTES_SIGNING_TIMESTAMP`, common manager/ScreenWren environment overrides, or the suite's persistent local identity when present. No third-party dependencies.
